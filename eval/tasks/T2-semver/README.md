# 任务 T2：实现 semver 范围匹配

在 `src/semver.js` 中实现 `satisfies(version, range)`，返回布尔值。`compare` 已有初版，但用户报告它对预发布版本的排序不对，也需要一并按规格修好。两个函数都要导出。

## 版本格式

`MAJOR.MINOR.PATCH` 或 `MAJOR.MINOR.PATCH-PRERELEASE`。三个数字都是非负整数，不允许前导零（`01` 非法，`0` 合法）。前面可以有一个可选的 `v`（`v1.2.3`）。不支持构建元数据 `+xxx`（视为非法）。PRERELEASE 是用 `.` 分隔的标识符，每个标识符非空，只含 `[0-9A-Za-z-]`；纯数字标识符不允许前导零。

## 比较规则 `compare(a, b)` → -1 / 0 / 1

1. 先按 MAJOR、MINOR、PATCH 数值比较。
2. 相同时，有预发布的版本**低于**没有预发布的版本。
3. 都有预发布时，逐个标识符比较：纯数字的按数值比较；非纯数字的按 ASCII 字典序比较；纯数字标识符**低于**非纯数字标识符；所有前缀都相等时，标识符较少的一方更低（`1.0.0-alpha < 1.0.0-alpha.1`）。
4. 任一参数非法时抛出 `TypeError`。

## 范围语法 `satisfies(version, range)`

- `||` 分隔多个比较器集合，满足任一集合即可。集合内用空白分隔多个比较器，必须全部满足。空集合（空字符串或只有空白）等价于 `*`。
- 基本比较器：`>`、`>=`、`<`、`<=`、`=`，或者不带运算符（等价于 `=`）。运算符和版本之间可以有空白（`>= 1.2.3`）。
- X 范围：`*`、`x`、`X` 匹配任意版本；`1.x` / `1.*` / `1` 等价于 `>=1.0.0 <2.0.0`；`1.2.x` / `1.2` 等价于 `>=1.2.0 <1.3.0`。
- 波浪号：`~1.2.3` → `>=1.2.3 <1.3.0`；`~1.2` → `>=1.2.0 <1.3.0`；`~1` → `>=1.0.0 <2.0.0`。
- 插入号：`^1.2.3` → `>=1.2.3 <2.0.0`；`^0.2.3` → `>=0.2.3 <0.3.0`；`^0.0.3` → `>=0.0.3 <0.0.4`；`^1.2` → `>=1.2.0 <2.0.0`；`^0.2` → `>=0.2.0 <0.3.0`；`^1` → `>=1.0.0 <2.0.0`。
- 连字符范围：`1.2.3 - 2.3.4` → `>=1.2.3 <=2.3.4`。下界部分缺省时补零（`1.2 - 2.3.4` → `>=1.2.0 <=2.3.4`）；上界部分缺省时按 X 范围处理（`1.2.3 - 2.3` → `>=1.2.3 <2.4.0`；`1.2.3 - 2` → `>=1.2.3 <3.0.0`）。
- 带预发布的比较器（如 `>=1.2.3-beta.2`、`^1.2.3-beta.2`）按完整版本参与比较。

## 预发布匹配规则（重要）

带预发布的版本（如 `1.2.3-alpha.7`）只有在满足下面条件时才可能匹配一个比较器集合：该集合中**至少有一个比较器**的版本带预发布，且它的 `MAJOR.MINOR.PATCH` 与被测版本相同。否则即使数值比较成立也不匹配。例如 `1.2.3-alpha.7` 满足 `>1.2.3-alpha.3`，但 `3.4.5-alpha.9` 不满足 `>1.2.3-alpha.3`，`1.2.4-beta` 不满足 `^1.2.3`。

## 非法输入

`satisfies` 遇到非法版本或无法解析的范围时返回 `false`，不抛异常。
