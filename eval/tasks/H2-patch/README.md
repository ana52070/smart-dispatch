# 任务 H2：应用 unified diff 补丁

`src/patch.js` 里有一个只能按行号硬套的补丁函数。请按下面的规格重写，导出 `applyPatch` 和 `PatchError`。

## 接口

```js
const { text, hunks } = applyPatch(source, patch, { fuzz = 0 } = {})
// hunks: [{ offset, fuzz }]，每个 hunk 一项，按顺序
```

失败时抛出 `PatchError`（继承 `Error`），它的 `hunk` 属性是出错 hunk 的序号（从 1 开始）。

## 源文本的行

- 按 `\n` 切行。`\n` 前面紧跟 `\r` 时，这一行的行尾是 `\r\n`，否则是 `\n`。不跟在 `\n` 前面的单独 `\r` 是行内容的一部分。
- 文本以换行结尾时，末尾不产生空行；文本最后一行没有换行时，这一行的行尾为空。空字符串没有任何行。
- **默认行尾**：源文本第一行的行尾；源文本没有行，或者第一行没有行尾时，用 `\n`。
- 比较行内容时不含行尾。

## 补丁格式

- 补丁按 `\n` 切行，每行末尾的一个 `\r` 去掉。第一个 `@@` 行之前的所有行（`diff`、`index`、`---`、`+++` 等）忽略。
- hunk 头：`@@ -a,b +c,d @@`，后面可以有任意文字。`,b` 或 `,d` 省略时表示 1。格式不对就抛错。
- hunk 内容逐行读取，直到旧侧行数达到 `b` 且新侧行数达到 `d`：
  - `' '` 开头是上下文行，同时计入旧侧和新侧；`'-'` 开头只计入旧侧；`'+'` 开头只计入新侧。行内容是去掉第一个字符后的部分。
  - 完全为空的行视为内容为空的上下文行。
  - `\` 开头的行（如 `\ No newline at end of file`）是标记，作用于它前面的那一行，不计入行数。标记出现在 hunk 内容的第一行时抛错。
  - 其他开头的行抛错。
  - 行数还没够就遇到下一个 `@@` 行或补丁结束，抛错。
- 一个 hunk 的行数凑够之后，紧跟的标记行仍然属于这个 hunk。之后直到下一个 `@@` 之间：空行忽略；以 `' '`、`'-'`、`'+'` 开头的行说明 hunk 的实际行数比头部声明的多，抛错；其他行忽略。
- 补丁里没有任何 hunk 时，原样返回源文本，`hunks` 为空数组。

## 定位

- hunk 中旧侧的行（上下文行和 `-` 行，按顺序）必须与源文本中连续的若干行逐行完全相同。
- **期望位置**（从 0 开始的行下标）：`b > 0` 时是 `a - 1`；`b = 0` 时（纯插入）是 `a`，表示插在第 `a` 行之后，`a = 0` 表示插在最前面。
- 所有 hunk 的行号都指**原始**源文本，与前面的 hunk 是否改变行数无关。
- 先在期望位置尝试；不匹配时，按距离 1、2、3……向两侧搜索，同一距离先试更靠前的位置。
- 每个 hunk 的匹配位置不能早于前一个 hunk 匹配区域的结束位置，也不能超出源文本末尾。
- `offset` = 实际位置 − 期望位置。

## 模糊匹配（fuzz）

- 先用 fuzz 0（完整匹配）在所有允许的位置搜索。找不到时，依次用 fuzz 1、2……直到 `options.fuzz` 重新搜索。**fuzz 小的匹配优先**，即使它的位置更远。
- 用 fuzz `f` 时，忽略 hunk 开头最多 `f` 行上下文和结尾最多 `f` 行上下文（只忽略连续的上下文行；开头或结尾的上下文不足 `f` 行时，有几行忽略几行）。被忽略的行不参与比较，也不会被替换，输出中保留源文本原来的这些行。
- `hunks[i].fuzz` 是这个 hunk 实际使用的 fuzz 值。
- 所有 fuzz 值都找不到位置时，抛出 `PatchError`。

## 末尾换行

- 旧侧的某一行（上下文行或 `-` 行）后面跟标记，表示它是源文本的最后一行，并且没有行尾。匹配时必须满足这一点。
- 反过来，如果旧侧某一行对应的是源文本中没有行尾的最后一行，这一行后面必须有标记，否则不匹配。
- 新侧的某一行（上下文行或 `+` 行）后面跟标记，表示它在输出中没有行尾。

## 输出的行尾

- 未被 hunk 替换的行保留原来的行尾。
- `+` 行使用默认行尾。
- 上下文行使用源文本中对应行原来的行尾；原来没有行尾时，使用默认行尾。
- 任何新侧行后面有标记时，这一行没有行尾。
