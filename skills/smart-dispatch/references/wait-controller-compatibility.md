# 等待控制器兼容性与验证摘要

本文件是**一次本地验证**的可复用摘要，不是永久保证。原始日志、会话记录、任务标识、机器指纹与安装路径不随本仓库分发；下文只保留可复核的结论、量级和边界。复现方式见仓库 `README.md` 的「验证」一节。

## 启用结论

门禁满足时，等待控制器在已验证的 Codex Code Mode 路径默认启用，不需要每次再次询问。不同主会话各自持有控制器，同一主代理的多个子任务使用批量等待；不建立全局单例或全局锁。用户明确要求不使用控制器时，以用户指令为准。

| 主代理宿主 | 状态 |
| --- | --- |
| Codex `functions.exec` / `functions.wait`（本次已测客户端与已安装伴生程序） | 已通过真实长等待，默认启用 |
| Claude Code、Antigravity、CodeBuddy 等其他主宿主 | 技能文件可按同一布局安装，等效执行入口尚未验证；沿用 `SKILL.md` 的原有阻塞及有限恢复规则 |

其他代理作为**执行子代理**时不需要具备 Code Mode。主会话为已验证 Codex 时，可以正常委托这些代理并用本控制器等待。

## 已测环境

- 验证时间：2026-11。
- 主会话客户端：Codex CLI 0.165（`functions.exec` / Code Mode 路径）。
- Codeg 桌面应用：0.42.1（生产安装）。
- 伴生程序：随 Codeg 安装的 `codeg-mcp`；隔离实验中复用同一已安装可执行文件。
- 本地源码后端测试来自另一份开发基线（0.41.3）。该基线的测试结果**不能**等同于生产 0.42.1 进程内的运行时状态。
- 验证过程未修改被委托代理、适配器、全局 MCP 配置或数据库。

## 真实长等待

单个 CodeBuddy 执行子代理被要求真实睡眠，主代理用控制器等待：

- 子代理侧真实睡眠 650.0 秒（单调时钟测量）。
- 控制器同一执行单元累计等待 1043.053 秒。差值来自子代理启动阶段先修正了自身命令引号错误，不能把全部时间计为睡眠时间。
- 四次串行等待调用：前三次各在约 300 秒返回客户端超时，控制器内部自动续等（每次仍严格 `wait_ms:0`）；第四次收取 `completed` 与预期标记文本。
- 过程中没有重新派发任务，也没有把 `wait_ms=0` 改成定时状态查询。外层仍通过恢复同一执行单元取回结果，不声称零模型唤起或零 token。
- 开始阶段的真实工具权限阻塞被控制器及时返回为可操作结果。平台强制授权仍需用户处理，技能不绕过。

## 真实超时与连接释放

使用已安装伴生程序、私有测试命名管道、自建测试令牌与本地模拟模型；不读取用户令牌，不接入真实业务 broker，不调用外部模型 API。

1. 显式 MCP `notifications/cancelled`：查询管道在测试进程退出前关闭，实测约 0.119 毫秒。
2. 同一 Codex 客户端把工具超时设为 1 秒并连续发起两次查询：观察到两个实际 `after 1000ms` 错误与两个取消通知，取消通知 ID 与请求 ID 匹配。
3. 两个查询管道均在取消通知后约 0.272 毫秒关闭；最大同时查询连接 1，结束后剩余 0。
4. 最后一次本地模型 HTTP 响应尚未返回时确认管道已关闭，因此释放不是由客户端进程退出触发。
5. 本地源码后端的 `infinite_status_wait_abandoned_when_peer_closes` 测试通过，表明该实现对端关闭时结束等待而不取消子任务。

**表述边界**：上述长等待与隔离释放是两套独立证据，不能合并成对生产 broker 内部计数（存活等待数、连接数、堆内存）的直接采样。

## 错误、批量与并发

- 控制器测试 **57 项全部通过**，覆盖结构化解包优先级、超时短语误判、正常耗时的无限续等与快重复熔断、三种 `blocked_on`、混合批次、24 个控制器实例并发互不串任务/计数/时钟、以及一个主代理对三个子任务分批等待并在每批后移除已完成 ID。
- 本地源码后端另有 8 项批量与父会话隔离测试通过（跨父会话不可见、无效令牌返回 `unknown`、任一完成即返回、多 ID 查询），以及 1 项上述对端关闭测试。这些属于本地源码测试，不是生产进程采样。
- 真实 MCP 参数错误通过控制器返回 `transport_error/invalid_arguments`，未重试。
- 以上并发证据是控制器逻辑测试与本地源码测试，**不是**多个真实主会话的整机压力测试。

## 尚未直接验证的范围

- 未对生产 Codeg 内部的存活等待任务数、连接持有时间或堆内存泄漏做直接采样。
- 一次与长等待并行发起的参数错误诊断调用约 128 秒后才返回；排队发生在哪一层尚未定位，不能据此断言旧查询泄漏，也不能保证所有并行调用无延迟。
- 超时边界附近的真实提问去重、多真实主会话高并发、应用退出或外层强制终止后的全部清理路径未做完整压力验证。应用异常退出的边界仍然保留未知。
- 其他主代理宿主（Claude Code、Antigravity、CodeBuddy 等）和后续升级的客户端未验证。无法绑定实际工具、无法加载可信核心或出现未知故障时应明确交接，不降级成循环轮询。
