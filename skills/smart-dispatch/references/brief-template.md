# 任务书模板

复制下面的骨架，去掉不适用的行，再从第 2 节挑选适用的场景检查清单附在后面。子代理看不到主对话，所以任务书里不能出现“如前所述”“按刚才的方案”这类指代。

## 1. 骨架

```markdown
你是执行子代理。你看不到主代理的对话，以下是完成任务所需的全部信息。

## 目标
<一两句话说明要达成什么。>

## 背景与已定决策
- <必要背景>
- <主代理已经确定、不需要再讨论的设计决定>

## 工作目录与相关文件
- 工作目录：<绝对路径>
- 入口和相关文件：<绝对路径列表；需要时注明行号>

## 允许的范围
- 可以修改：<文件或目录>
- 必须保护：<未提交改动、用户文件、配置等>
- 禁止：<切分支、重置、删除、联网、安装、改全局配置等>

## 步骤与要求
1. <主代理确定的关键步骤；常规实现细节由你自己决定>

## 验收标准
- <可以检查的结果>
- <必须运行的命令及期望输出>

## 长命令与后台进程
- 单条命令预计超过 10 分钟时，开始前在回复中写明命令用途和预计时长。
- 交付前结束你启动的所有后台进程。确实需要保留的，在报告里列出 PID、命令和用途。

## 问题返回协议
普通技术问题交回主代理。不要调用面向用户的提问或计划审批工具。任务书、源码和合理默认值能确定的细节，自己处理。需要主代理决定时，停止受影响的工作，保留已完成的成果，把“需要主代理决策”作为本轮最终报告返回，不要停在原地等用户回答。报告包含：问题、证据、已尝试的方法和结果、当前改动、可选方案和建议、需要主代理决定的事项。

同一个问题最多做两轮有效尝试，每轮必须基于新证据或不同的修法。两轮后仍失败，按上面的格式返回。

## 交付格式
- 状态：已完成／需要主代理决策／失败
- 完成内容：
- 变更位置：（绝对路径）
- 验证证据：（实际命令、结果、未执行的项目和原因）
- 后台进程：无／（PID、命令、用途）
- 问题与风险：
- 交接信息：
```

## 2. 场景检查清单

只附与本次任务相关的条目。

### 远程主机、开发板、硬件

- [ ] 写明主机、用户和连接方式。凭证只写在任务书里，不要求写入任何文件或日志。
- [ ] 改动系统服务、`/opt`、`/etc` 前先备份，并写明回滚命令。
- [ ] 说明目标机能否联网。离线时提供离线安装包的位置。
- [ ] 写明哪些服务不能启动或重启，例如会驱动执行机构、会切断网络的服务。
- [ ] 动态库、RPATH 等路径不能依赖源码或构建目录。

### Windows 与跨平台

- [ ] 在 Windows 上编辑会在 Linux 运行的脚本时，保持 LF 换行，交付前检查。
- [ ] 中文路径和文件名注意编码，解压时保持原始文件名。
- [ ] PowerShell 和 Bash 的语法不要混用，命令里写清用的是哪个 shell。

### 仓库与代码

- [ ] 写明当前分支，说明是否有未提交的改动要保护。
- [ ] 写明必须通过的测试或构建命令。
- [ ] 不提交、不推送、不开 PR，除非任务书明确要求。

### 浏览器与在线系统

- [ ] 明确哪些操作只能查看。筛选、勾选、排序也可能改变已保存的页面状态，没把握时先截图。
- [ ] 涉及下单、提交、发布等不可逆操作时，必须交回主代理决定。

### 长时间任务

- [ ] 给出预计耗时。超过 10 分钟的单条命令，要求子代理先声明预计时长。
- [ ] 要求前台执行，或者在交付前结算所有后台任务。
