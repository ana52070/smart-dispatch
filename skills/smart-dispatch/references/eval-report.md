# 协作效果实测记录

本文件记录 smart-dispatch 的对照实验，用来支撑 `SKILL.md` 里的委托收益判据。评测框架与原始数据在仓库的 `eval/` 目录。

## 第一轮：规格密、代码短的题目（2026-11-16）

### 设置

- 题目：7 道自带隐藏测试的编程题，均为 1–3 个文件、几百行以内的实现，规格中规则多、陷阱多。
  - T1 限流器修复、T2 semver 范围匹配、T3 多文件配置加载器、T4 流式 CSV 解析器；
  - H1 带重试/超时/取消的异步队列、H2 unified diff 补丁应用、H3 glob 匹配。
- 分组：
  - A：Opus 单干；
  - B：Flash 执行代理单干；
  - C：Opus 主代理 + Flash 执行代理，技能 1.1；
  - D：Opus 主代理 + Flash 执行代理，技能 1.2（加入验收先行、保留用例、原文不转述）。
- 质量：隐藏测试通过率，作答方看不到隐藏测试。
- 成本：主代理会话的 token，按 Opus 相对价格折算为“加权 token”（输入 ×1、缓存写入 ×1.25、缓存读取 ×0.1、输出 ×5）。
- 限制：Codeg 只允许一层委托，协作组的主代理按“规划会话 → 执行代理 → 验收会话”分阶段接力运行。验收会话是冷启动，比真实单会话多出约 3.5 万–4 万加权 token。

### 结果

| 组 | T1–T4 质量 | H1–H3 质量 | 主代理加权 token（每题） | 单题耗时 |
| --- | --- | --- | --- | --- |
| A Opus 单干 | 100% | 100% | 5.8 万–16.9 万 | 1–8 分钟 |
| B Flash 单干 | 100% | 100% | —（不使用 Opus） | 8–37 分钟 |
| C 协作 1.1 | 100% | 未测 | 15.0 万–19.3 万 | 约 15–40 分钟 |
| D 协作 1.2 | 100% | 未测 | 16.8 万–20.5 万 | 约 15–40 分钟 |

### 结论

1. **质量没有下降**：协作组与单干同为 100%。1.2 的保留用例在 D-T3 中发现了一处执行代理遗漏（`key in schema` 误中内置属性），由主代理亲自修复。
2. **这类题委托不省 token**：规划阶段单独就花了 7.8 万–10.7 万，和 Opus 单干整题的成本相当；主代理写任务书与用例表的输出量（8k–12k）不少于直接写实现（5k–11k）。扣除接力冷启动开销后，协作组主代理成本仍与单干持平或更高。
3. **执行代理更慢**：Flash 单干每题 8–37 分钟，Opus 单干 1–8 分钟。
4. **环境问题**：Antigravity 有两次在“后台运行 npm test 后等待”时挂起（代码已写完或尚未开始），需要按停滞规则处理。

因此 1.3 把“按文件数和编辑次数决定是否委托”改成“按执行量与说明量之比决定”。

## 第二轮：执行量较大的题目（2026-11-17）

### 设置

- E1：跨 24 个模块的日志 API 迁移，包含别名导入、动态级别、只转换顶层键、同名本地函数不能动等陷阱；隐藏测试逐个模块检查返回值和日志。
- E2：订单报表管道排障。4 个根因分散在不同模块，第一个会导致直接崩溃，修掉后其余症状才暴露；运行时输出 4000 多行调试日志。
- 分组：A（Opus 单干）与 D3（Opus 主代理 + Flash，技能 1.3）。

### 结果

| 组 | E1 质量 | E1 主代理加权 token | E2 质量 | E2 主代理加权 token |
| --- | --- | --- | --- | --- |
| A Opus 单干 | 100% | 8.8 万 | 100% | 7.8 万 |
| D3 协作 1.3 | 100% | 12.7 万 | 100% | 8.3 万 |

D3 的主代理在两道题上都按委托收益判据判断“写任务书的篇幅和直接改差不多”，**选择不委托**，自己完成。成本因此接近单干，多出的部分来自读技能文件和额外的自检脚本。第一轮“必须委托”时，成本是单干的 1.4–2.9 倍。

## 总结

1. **质量**：9 道题、所有分组都是 100%，没有观察到协作导致的质量下降。保留用例能抓到执行代理的遗漏，由主代理补上。
2. **成本**：对 Opus 一两分钟、十万 token 以内就能完成的任务，委托一定更贵。1.3 能识别并避开这种情况，把多余开销压到单干的 0–45%。
3. **委托真正省 token 的场景**这两轮都没有覆盖：需要几十上百次命令、反复构建部署、看大量日志的长任务（参考会话里的单个任务消耗 6000 万–1 亿 token）。在这种任务上，执行代理承担的执行量才远大于主代理的说明量。要验证这一点，需要用真实的长任务来测。
4. **速度**：执行代理单题耗时是 Opus 的 5–10 倍；Antigravity 有 3 次在“后台运行命令后等待”时挂起。
