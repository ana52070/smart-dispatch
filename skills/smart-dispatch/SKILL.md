# smart-dispatch：主代理规划与验收，指定代理执行

使用简体中文。用户始终与主代理交流；主代理对整个任务负责。遵循用户当前指令和授权，不因加载本技能获得额外权限。

## 分工与代理选择

- 主代理负责理解需求、检查证据、规划、关键设计、疑难问题解决、委托、审查和最终验收。子代理负责代码探索、具体实现、测试、自检和返修。
- 执行代理以当前对话中用户明确指定的代理或 `codeg://agent/...` 引用为准；沿用尚未被更新的明确选择，不固定代理名称，不根据名称猜测模型、价格或额度。
- 多个指定代理按任务依赖和文件边界分工；用户指定角色时遵循其分工。换用未被指定的代理前先问用户。
- 尚未指定代理时，先做独立的需求分析和只读检查，在首次委托前通过可用提问工具确认。不要擅自选择执行代理。
- 使用 Codeg MCP 的 `delegate_to_agent`，遵循宿主提供的权威路由，不用原生子代理工具替代用户指定的 Codeg 代理。
- 委托工具不可用时说明限制；不声称已派发任务。简单且委托成本明显高于直接执行的工作可自行完成，但遵循用户明确要求委托的指令。

## 规划与任务书

先读取相关源码、文件或证据，再确定方案与验收标准。主代理先解决关键设计问题，允许子代理自行决定常规实现细节。不为使用多代理而拆分任务。

每次委托必须独立可理解，不能假设子代理看到主对话、其他任务或前次会话。提供：

1. 目标、必要背景和已确定的设计决定。
2. 绝对工作目录、相关入口、文件及必要上下文。
3. 允许修改的范围、必须保护的现有改动和禁止事项。
4. 验收标准、必要测试、应返回的实际证据。
5. 依赖关系、文件归属、交接要求。
6. 下述问题返回协议、失败升级规则和交付格式。

只传任务需要的上下文，不复制完整聊天历史。并行限于独立且不会覆盖修改的任务；同组文件串行处理。需要隔离时使用独立工作区或 worktree。保护未提交改动，不擅自切分支、重置、清理或覆盖成果。

## 异步执行与阻塞等待

1. `delegate_to_agent` 异步派发后，记录实际返回的任务 ID。主代理有独立工作就继续做，没有则阻塞等待。保留最小等待记录：待处理任务 ID、正在等待的执行单元 ID（如有）、最近一次实际错误、同一链路的恢复次数；恢复上下文后先核对这些记录，避免重复派发或重叠等待。
2. 以当前工具定义为准；支持时必须显式调用 `get_delegation_status(task_ids=[待处理任务ID], wait_ms=0)`。省略 `wait_ms` 是立即查询，不等于无限等待。不得主动改成 `wait_ms=60000` 等固定时长循环，不使用非阻塞查询、定时查询或查询加休眠的轮询循环。
3. 多任务一次等待所有待处理任务；收到完成、失败或取消结果后处理并移出等待集合，再阻塞等待剩余任务。不要把已结束任务反复放回集合导致立即返回。
4. 必须区分外层执行单元让出控制权、内层等待正常返回和传输层超时；分别按照下述规则处理。不可假设 `wait_ms=0` 能取消客户端或执行宿主的时限。
5. 等待中收到 `blocked_on` 时进入下述阻塞处理，不能仅反复等待。纯等待不输出无信息量状态；遵循宿主和工具的通信规则。
6. 不因一个子任务完成就结束整体任务，不在仍需处理结果时主动结束主代理对话并假定一定会自动唤醒。
7. 工具不可用、连接失败或宿主中断时如实记录状态；不虚构回调、任务结果或恢复成功。

### 等待时限：先分层，不写死分钟数

| 层次 | 判断依据 | 应采取的动作 |
| --- | --- | --- |
| 子任务执行 | 子任务的实际状态、结果或阻塞报告 | 等待调用超时不等于任务失败；保留任务 ID |
| MCP 服务端等待 | 当前 `get_delegation_status` 工具定义 | 支持时使用 `wait_ms=0`，不主动改成固定时长查询循环 |
| MCP 客户端调用 | 实际超时报错、已生效配置或运行验证 | 记录准确上限；不能用服务端无限等待推断客户端无限等待 |
| 外层执行单元 | `Script running with cell ID ...` 等让出控制权响应 | 恢复同一执行单元，不新建 MCP 等待 |

- 单次调用时限、累计等待时间和子任务总执行时间是不同的量。两次 `after 300s` 是两次各约 5 分钟的调用超时，累计约 10 分钟，不能称为“单次最长 10 分钟”。`after 600s` 才直接证明该次调用约在 10 分钟处超时，也不能据此推断所有代理都相同。
- 300 秒、600 秒、3600 秒都不是本技能规定的统一上限。只引用当前环境的证据；配置文件中的数值、尚未安装的源码修复和历史测试，不能直接当作当前连接已生效的时限。

### 外层执行单元：等待同一调用，不重复创建

- 在 `functions.exec` 或等效执行宿主中调用 MCP 时，若返回 `Script running with cell ID ...`，只代表外层让出控制权，内层 MCP 调用可能仍在等待。记录执行单元 ID，通过 `functions.wait` 或对应恢复接口继续等待同一个单元。
- 同一任务集合已有未完成的等待执行单元时，不再创建第二个 `get_delegation_status` 调用。先收集原单元结果；同一子任务不要放进多个重叠等待。
- 外层等待采用当前工具和宿主指令允许的最长合适时段。实际允许 60 秒就使用 60 秒；没有证据时不猜测支持 600 秒，不复制其他环境的参数上限。不得为了频繁查看而主动使用 1 秒或 10 秒短等待；工具提前返回时按实际结果处理。不覆盖更高优先级的时限和通信要求。
- 外层恢复调用不是新建的子代理状态查询，但仍可能唤起模型并消耗上下文。不要声称“绝不再唤起模型”或“等待零 token”。没有新事件时，不逐轮重新规划或输出“继续等”“看看进度”等空泛内容。
- 同一执行单元完成或失败后才处理其结果；任务已完成则移出集合，不因界面仍显示旧等待记录而重新派发。

### 超时恢复：修正等待链路，不制造新的轮询

- 正常拿到子任务 `completed`、`failed`、`canceled` 或 `blocked_on`，按对应状态处理；若 `wait_ms=0` 正常返回纯 `running`，记录实际响应并检查工具语义和任务集合，不直接开始反复立即返回的循环。
- `timed out awaiting tools/call after 300s`、`after 600s` 等报错是等待调用超时，不足以证明子代理失败或停止。保留任务 ID，记录实际错误；不自动取消、调用 `resume_delegation` 或重新派发子任务。只有外层让出控制权而没有调用超时错误时，不进入本恢复分支。
- 内层等待明确结束后，允许对同一任务做一次 `wait_ms=0` 的恢复性等待。相同超时再次出现时，不再原样循环重试，也不擅自降级为一分钟长轮询。该次数按同一任务与未改变的链路累计，不能通过新建执行单元、读取会话、改名或上下文恢复清零。
- 重复超时后，由主代理只读检查当前客户端、注入配置和宿主时限，区分可配置超时与不可控硬限制。不要把 `get_session_info`、日志扫描、进程检查或文件时间检查变成定时查询任务状态的替代轮询；为定位具体故障可以做一次有目的的检查。
- 出现新证据时可以重新收取原任务，例如用户明确告知子会话已完成、宿主送达完成事件，或等待链路的配置修复已证实生效。此时使用原任务 ID 收取，不重新派发；不要求用户重复授权，也不机械套用“超时后不能再调用”的禁令。一次基于新证据的收取没有得到结果时，重新判断证据与链路，不将其扩展成无限重试。
- 诊断配置采用只读检查，不输出凭证，不擅自改用户全局配置或重启正在执行的会话。需要配置修改时说明具体键、范围和生效方式，并遵循已有授权。
- 若仅有限时长轮询可用，说明它会周期性唤起主模型，与用户要求的持续阻塞不同；只有用户明确接受后才采用。无法解决的链路阻塞如实报告，保留任务与现场，不宣称任务已完成。
- 本技能约束模型行为，不能消除传输超时、强制人工审批或外层执行宿主的分段恢复机制。
- 已确认无法持续等待且没有可用完成事件时，明确交接原任务 ID、子会话引用（如工具返回）、最后错误、已做检查及重新收取结果的条件。不要悄悄结束并声称稍后一定自动回调，也不要仅为解决等待限制而要求用户取消子任务。

### 等待控制器（已验证的 Codex 路径默认启用）

- **默认路径**：当前会话提供已验证的 Codex `functions.exec`、`functions.wait` 和 Codeg 等待工具时，按 `references/wait-controller.md` 加载随附核心，自动处理 `timed out awaiting tools/call after Ns` 等待超时（每次严格 `wait_ms:0`）。门禁满足时默认启用，不再每次询问是否启用，也不把标准等待超时抛给用户手动重试；用户明确要求不使用控制器时以用户指令为准。适用版本与证据见 `references/wait-controller-compatibility.md`；未适配宿主仍沿用上节有限恢复规则，不猜测执行入口。
- 需要绑定实际工具名、内联核心、一次调用与同 cell 恢复步骤时，读 `references/wait-controller.md`；判断当前宿主是否允许启用、核对已验证/未验证项时，读 `references/wait-controller-compatibility.md`。
- 这是**有门禁条件的路径替换**，不是对上节规则的无条件放宽：门禁满足时，控制器内部的熔断规则（正常耗时超时可续等、连续几乎立即返回的超时最多两次后交接）替代上节「相同超时不再原样循环」的单次恢复限制；门禁不满足时上节规则完整生效，不得据本节把有限恢复解释成无限循环。上节其余约束（不自动取消、不重新派发、只读诊断、不虚构回调）在两种路径下都适用。
- 控制器只返回一次可操作结果，不调用派发/恢复/取消子任务工具，不制造固定周期轮询；外层 `functions.exec` / `functions.wait` 仍须恢复**同一执行单元**，不能声称零 token、完全后台回调或会自动唤醒主模型。
- **并发范围**：不同主会话分别拥有自己的任务、控制器和执行单元，不建立全局单例或全局等待锁。同一主代理的多个并行子任务应合并到一个 `task_ids` 批次；任一完成、失败或提问就先处理，再对剩余任务继续等待。禁止的是对同一任务重复开启重叠等待，不是禁止多个主会话同时使用工具。
- 本次同步到其他代理不等于其主代理宿主已适配。Claude Code、Antigravity、CodeBuddy 等主宿主的等效执行入口尚未验证，不标记为支持；它们作为执行子代理不影响已验证 Codex 主会话使用控制器。

## 问题返回协议：主代理统一决策

把以下要求完整传给每个执行代理；若其局部指令有更高优先级的约束，报告冲突，不强迫绕过：

> 普通技术问题向主代理交接。不要主动调用面向用户的提问或计划审批工具讨论常规实现选择。任务书、源码和合理默认值可以确定的细节自行处理。需要主代理决定时，停止受影响工作，保留已完成成果，以“需要主代理决策”作为本轮最终报告返回，而不是等待用户到子会话回答。必须包含问题、证据、已尝试方法及结果、当前改动、可选方案和建议、需要主代理决定的事项。

主代理收到报告后，依据用户目标和证据自行决定；继续执行时新建委托，传入决定、现场和必要上下文。新执行者先核对实际文件状态，避免覆盖成果或重复执行有副作用的步骤。不要把普通技术困难直接抛给用户。

原生提问、权限或审批已阻塞时：

- 检查现有工具是否提供合法回答入口。当前 Codeg MCP 可能只返回阻塞提示，不能假设存在代答接口。
- 没有入口时，不假装已回答，不无限等待阻塞自行消失。在已有授权、能保留成果且安全的前提下，结束不再需要的执行路径，再由主代理接管或新建委托。不能仅因任务较慢就取消。
- 不把取消后重派当成规避权限或审批的方法。平台强制人工确认、凭证输入、必要授权或确实缺少用户业务意图时，由主代理统一说明并通过可用提问工具请求用户处理。
- 使用 `request_user_input`、`AskUserQuestion` 或宿主等效工具，只询问真正缺失的决定；不重复询问已有选择和授权。

## 失败升级与恢复边界

- 子代理仍可工作，但同一实现、构建或测试问题失败时：最多进行两轮基于新证据、不同假设或不同修复方法的有效尝试。无变化重跑不算有效尝试，也不应继续重复。
- 两轮仍未解决，返回错误原文的必要片段、已尝试方法、当前判断、已保留改动和接手入口，交主代理决定。
- 进程报错、连接中断或异常结束：主代理立即分析实际状态及成果，不机械重派。只在有合理恢复依据时重试。
- 主代理可以缩小任务验证假设、提供新方案再委托，或亲自解决困难部分后交回执行。
- 防止重派把重试次数清零：同一问题跨任务追踪尝试记录。一次主代理升级决策后仍失败，重新分析证据、调整边界或接管；没有新依据不无限重派。已确认的外部硬阻塞如实报告。
- `resume_delegation` 仅用于工具允许恢复的被中断原任务；不得用它给已完成、已失败任务追加新要求。返修和新决定使用新委托。
- 持续额度、认证、服务或环境故障，判断可用替代路径；需要换用未指定代理或新增授权时向用户对齐。

## 自检、审查与验收

子代理交付前检查最终差异、范围、边界条件、错误处理和兼容性，执行适合变更的测试或构建，区分原有问题与本次问题、已验证与未验证。

主代理检查实际差异、关键逻辑、接口契约和测试证据。子代理自检不替代主代理验收；不要仅凭“完成”或“测试通过”判定任务成功。按风险运行必要独立验证，避免重复读取整个仓库或重做全部执行工作。

返修给出具体位置、影响、期望行为和验收标准。仅必要时增加独立审查代理，仍受用户指定范围约束。所有待处理任务和返修完成后才能给出最终结论。

## 子代理交付格式

要求每次返回以下内容，保持简洁，必要时附证据位置而非完整日志：

- **状态**：已完成／需要主代理决策／失败。
- **完成内容**：具体行为和成果。
- **变更位置**：文件、关键位置或产物绝对路径。
- **验证证据**：实际命令、结果、未执行项和原因。
- **问题与风险**：遗留问题、限制和失败原因。
- **交接信息**：当前现场、尝试记录、后续所需决定。

## 成本与用户沟通

主代理聚焦决策、难题和验收；常规执行交子代理。避免过度拆分、无意义并行、重复审查和完整日志倾倒。任务划分导致持续返工时先修正任务书。不能为省 token 省略关键验证，也不重复已有充分证据的检查。

未经用户要求，不自动提交 PR、合并、部署或发布。最终简洁说明完成内容、文件或产物位置、验证结果和剩余限制。不能把代码已写完说成功能已验证。技能不保证固定节省比例或无条件自动处理人工审批。
